# GPT Image 2.5 research note

Retrieved: 2026-09-16

Scope: facts needed to move Lively Photos Director from a DALL-E-era prompt compiler to an engine-aware OpenAI image generation and editing contract.

## Source policy

Only first-party OpenAI documentation is authoritative for the OpenAI adapter. Model aliases and endpoint contracts can change, so the adapter must keep current facts in one progressive reference instead of repeating them across Skills, CLI copy, and listing metadata.

## Engineering decisions

These are repository decisions derived from the verified contract, not claims made by OpenAI.

1. Keep five public Skills. GPT Image 2.5 becomes a deep engine reference owned by `engine-prompt-compiler`, not a sixth public Skill.
2. Separate four layers: portable photographic intent, reference-role map, engine request parameters, and engine-specific prompt text.
3. Use capture profile separately from scene mode. `everyday-lifestyle + phone-candid` and `editorial-natural + editorial-camera` should produce different framing and imperfection behavior even when the scene is similar.
4. Treat focal length/aperture language as visual direction cues. Do not claim exact optical simulation or numerical camera calculation by the image model.
5. Prefer the smallest revision that matches the defect. Escalate model choice or quality only when the failure class justifies it.
6. Keep other engines as supported compiler families only where current vendor facts are available. Do not freeze stale Midjourney, Flux, or SDXL flags as universal 2026 truth.

## Known evidence gaps

- No authenticated GPT Image API execution was available in this ChatGPT session, so no Flare-vs-Sunburst runtime benchmark is claimed here.
- Plugin Eval and Qodo require local CLI execution. The authorized desktop executor was offline during this work, so their runtime reports are not claimed.
- GitHub Actions will provide repository-native verification after the PR is opened. Until those checks complete, runtime validation remains pending.
